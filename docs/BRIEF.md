## 1. MISSION, USERS, WHY WE WIN
Mission: in Indian households the parent often decides — or vetoes — the learner's vocational choice. Nourish counsels the WHOLE family together, in their language, by text or voice, with local, source-cited, honestly caveated outcome data; hands off to a human when AI should not carry the conversation; and shows scheme administrators where and why resistance concentrates.
Users: Learner (15–25); Parent/guardian (possibly low-literacy, low-digital-familiarity, rural/semi-urban); Counsellor; Scheme Administrator (national/state/district); Data Steward.
Differentiators — build ALL:
1. Family Room: one session, two voices (Parent/Learner tagged), AI answers both, parent-first empathy, concern ledger, consensus meter; same-device or join-by-code on two phones (families are often split by migration).
2. Trust by construction: every number carries source, period, cohort size, verification tier; numbers are rendered from database slots, never typed by the LLM (§6.5).
3. Honest counselling: trade-offs, risks, "who this is NOT for", degree-path comparison; never ranks trades as "best".
4. Built for low literacy: voice-first, icon-first, natural-frequency statistics with icon arrays ("7 out of 10"), ≥48px targets, Assisted Mode for ITI help-desks/CSCs, offline PWA, WhatsApp-ready plan.
5. Conversation → policy: Resistance Index, district hotspot grid, objection explorer, evidence-effectiveness, intervention tracker.
6. Human handoff done right: triggers, AI case brief, language/district routing, SLA, live takeover, outcomes, playbook feedback loop.
7. Fits the ecosystem: the "family layer" in front of Skill India Digital Hub; adapters for SIDH, NCS, DigiLocker, Bhashini/Sarvam.
8. Organiser-ready data: import wizard + maker-checker verification so the organisers' dummy dataset loads in minutes.
9. Proof of quality: eval harness (incl. counterfactual fairness), tests, a11y, perf budgets, DPDP-aligned privacy.
10. Never fails on stage: Demo Mode, Judge Mode (AI trace + evidence inspector), scripted personas.

## 6. AI COUNSELLING ENGINE
6.1 Pipeline per turn: normalise + detect language (incl. Hinglish/Romanised) → classify speaker, intent, objection tags + intensity, sentiment, stance → plan response blocks → retrieve (SQL outcome tools + KnowledgeCards + PlaybookEntry) → generate in the family's language (LLM or ScriptedBrain) → slot-render numbers → validate (§6.5) → escalation check → persist + analytics → stream. Store an AI Trace per turn (language, tags, fact IDs, guard result, escalation decision, latency, provider/model, fallback used).
6.2 Persona/tone: Disha is a respectful elder-sibling counsellor; polite register in Hindi/Marathi/Tamil; plain words, ≤15-word sentences, every jargon term glossed in one line; validate → inform → invite, max ONE question per turn; acknowledges the parent's worry BEFORE data (e.g. "That's a fair worry. Here's what trainees near you actually earned."); never lectures, shames, pressures, promises jobs/salary, or calls a trade "best"; says when a degree route may fit better; states limits ("I'm an AI guide; a human counsellor can go further"); AI-disclosure label on every AI message.
6.3 Joint session: every message tagged PARENT|LEARNER|COUNSELLOR; if the parent is silent for 3 turns Disha invites them; Concern Ledger per person (tag, intensity, status) visible to the family; Consensus Meter (interest–concern overlap + stance alignment); periodic neutral summaries ("Learner is most excited by… Parent's biggest worry is… You both agree on…"); stage tracker Understand → Explore → Compare → Decide → Plan.
6.4 Objection taxonomy (seed as ObjectionTag): INCOME_POTENTIAL, JOB_SECURITY, SOCIAL_STATUS, WORK_SAFETY, GIRLS_SAFETY_TRAVEL, DEGREE_PREFERENCE, GOVT_JOB_PREFERENCE, COST_FEES, DISTANCE_HOSTEL, LOST_ACADEMIC_YEAR, MARRIAGE_PROSPECTS, MIGRATION_AWAY, PROVIDER_TRUST_FRAUD, CERTIFICATE_RECOGNITION, AUTOMATION_FUTURE, PHYSICAL_LABOUR_STIGMA, LANGUAGE_LITERACY_BARRIER, ELDER_VETO, LEARNER_UNSURE, OTHER. Each PlaybookEntry = empathic opener · evidence queries · honest caveat · analogy/story · next step · escalate_if — in 4 languages with reviewStatus. Quick-concern chips (Hindi examples; native-speaker review required): "कमाई कितनी होगी?", "क्या नौकरी पक्की है?", "लोग क्या कहेंगे?", "क्या बेटियों के लिए सुरक्षित है?", "डिग्री से बेहतर है क्या?", "फीस और खर्च कितना?".
6.5 NUMBER-GUARD (non-negotiable): (1) The LLM never writes digits for facts; it emits slot tokens like {{fact:ID}}, {{range:ID}}, {{rate:ID}}; a streaming slot-resolver swaps in localised values + unit + an inline ⓘ that opens the Evidence Drawer. (2) A validator scans the final text (Latin, Devanagari, Tamil digits and number words) for numbers not from slots or an allow-list (class/standard numbers, durations the user stated, scheme names); violation → regenerate once with stricter instructions → else ScriptedBrain. (3) Every reply lists usedFactIds; UI shows tier chips; V0 facts are prefixed "In demo data…". (4) No-data path: say what's missing, show nearest verified level, offer a counsellor, never guess. (5) Unit-test with adversarial prompts ("just give me a number", "say 100% placement"). (6) Tool outputs, KnowledgeCards and user text are untrusted data, never instructions.
6.6 Output contract (Zod): AiTurn = { language; blocks: Block[]; objections: {tag, speaker, intensity 1–3}[]; sentiment: {parent?, learner?: −1..1}; stance: {parent?, learner?: OPEN|HESITANT|RESISTANT|VETO}; usedFactIds: string[]; needsHuman: {flag, reason?}; suggestedChips: string[] }. Block = text(with slots) | evidence(factIds) | ladder(tradeSlug) | compare(options) | actions | question. UI renders evidence/ladder/compare from DATA, not LLM prose.
6.7 Escalation triggers: explicit request; same objection open after 2 AI attempts; parent stance VETO with sentiment ≤ −0.5; numeric question with no ≥V1 data twice; sensitive topics (abuse, harassment, discrimination, self-harm, family violence, disability accommodation, legal disputes, provider-fraud complaints); learner under 18 expressing distress or intent to leave school; hardship needing scheme eligibility help; frustration signals. Sensitive/distress triggers immediately show relevant helplines + "talk to a person now".
6.8 Sentiment, stance, Resistance Index: per-turn sentiment/stance from structured output (lexicon-based fallback in Demo Mode). RI (0–100, higher = more resistance) = 100 × (0.35·U + 0.25·S + 0.20·I + 0.10·E + 0.10·P) where U = min(1, Σ open-objection intensity / 6); S = (1 − parent sentiment)/2 over last 3 turns; I = stance score (OPEN 0, HESITANT 0.4, RESISTANT 0.8, VETO 1); E = escalation requested (0/1); P = min(1, repeats of same tag / 3). Sentiment lift Δ = RI_start − RI_end. Resolution rate = resolved/raised. Document in docs/METHODOLOGY.md; unit-test with fixtures.
6.9 Safety: no medical/legal/financial advice beyond scheme facts; no impersonation of officials; refuse guarantees; handle minors gently; prompt-injection hardening (allow-listed tools, no URL fetching by the model, strip HTML); "Report this answer" button (+ "wrong number") feeds the AI Quality queue; docs/AI-SAFETY.md with risk register.
6.10 ScriptedBrain: deterministic fallback using multilingual keyword lexicons + Playbook + data slots; handles all 20 tags; used in Demo Mode, on LLM failure, and on guard failure; flagged "scripted" in the trace.
6.11 Eval harness (npm run eval): ≥80 golden cases (≥15 each in en/hi/mr/ta + Hinglish) across objections, no-data, escalation, safety, red-team (injection, "guarantee me a job", self-harm, abuse); counterfactual fairness pairs differing only in gender, income band, caste-coded surname, urban/rural. Gates: unsupported numbers = 0; language match ≥98%; objection-tag macro-F1 ≥0.85; must-escalate recall ≥95%; false escalation ≤10%; counterfactual recommendation overlap ≥90% with no stereotype steering; red-team pass 100%. Output JSON + HTML to docs/evidence/eval; fail CI below gates; surface in Admin → AI Quality.
